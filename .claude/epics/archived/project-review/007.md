# Task: Dogfood hierarchical review policy in Agent Kit

## Description

Adopt root and nested review guidance in Agent Kit itself and route repository
review requests through the new skill by default.

## Acceptance Criteria

- [x] Root guidance covers repository-wide resource, security, privacy,
      portability, distribution, release, and review-signal concerns.
- [x] Nested guidance under `skills/project-review` covers trusted-base,
      canonical-result, analysis-only, path, command-authority, and output
      boundaries.
- [x] `AGENTS.md`, and therefore Claude Code through `CLAUDE.md`, directs agents
      to use `project-review` for reviews unless explicitly told to use another
      method.
- [x] Change reviews obtain the reviewer from an independent installation or
      trusted starting revision and cannot bootstrap acceptance from a skill
      introduced or modified by the reviewed state.
- [x] Repository validation requires the root policy and an integration test
      proves the root and nested guidance chains.
- [x] Public documentation explains the dogfood setup and its trusted-base
      activation behavior.
- [x] Agents may evolve the nearest review policy for durable, already-agreed
      invariants without proliferating generic per-skill files or silently
      introducing new policy.

## Completion Evidence

- The explicit-path resolver returned `REVIEW.md` for a root target and both
  `REVIEW.md` and `skills/project-review/REVIEW.md` for a nested skill target,
  with no limitations.
- The focused routing, hierarchy, and evaluation checks passed, and
  `quick_validate.py` accepted the skill metadata and structure.
- `python scripts/agent_kit.py check` passed 132 tests with one intentional
  platform-dependent skip and left the worktree unchanged.
- A fresh agent selected `project-review` from a plain review request, found the
  self-review bootstrap flaw, and a separately selected static bootstrap review
  returned `PASS` after the trust-boundary correction.
- Follow-up policy tests distinguish relevant pre-existing suggestions from
  touched-code blockers, require explicit evidence rules in the nested policy,
  and preserve the constrained AGENTS guidance against per-subtree proliferation.
