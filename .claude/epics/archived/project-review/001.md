# Task: Define contracts schema and calibration

## Description

Turn the approved design into exact v1 contracts before implementation fans out.
Define the canonical JSON Schema, field semantics, verdict derivation, finding
calibration, path representation, guidance provenance, command authorization,
limits, and CLI seams for the two deterministic helpers.

## Acceptance Criteria

- [x] `review-result.schema.json` defines `schema_version` `1.0.0` and rejects
      unknown or structurally invalid fields.
- [x] Target, guidance, coverage, verification, findings, and limitations have
      provider-neutral required fields and documented invariants.
- [x] `PASS`, `BLOCK`, and `INCOMPLETE` derivation is unambiguous, including a
      known blocker alongside incomplete coverage.
- [x] Disposition, severity, confidence, category, and scope relation are separate
      and calibrated with positive and negative examples.
- [x] Stable display IDs and cross-run fingerprints have a deterministic contract.
- [x] Resolver and result-tool CLI input/output, exit codes, and size bounds are
      specified without permitting arbitrary command passthrough.

## Technical Details

Keep machine compatibility ahead of convenience. Prefer `additionalProperties:
false`, repository-relative POSIX paths, bounded strings/arrays, and explicit
enumerations. Treat JSON as data and avoid provider-specific agent identifiers.
