# Task: Add eval candidate audit

## Description

Deliver the analysis-only `eval-candidate-audit` skill for turning explicitly
selected session evidence into bounded, deduplicated evaluation candidates.

## Acceptance Criteria

- [x] The skill accepts only caller-selected or project-opted-in eligible
  session inputs and never performs global automatic transcript analysis.
- [x] Private raw transcripts remain local and are neither committed nor copied
  into portable candidate output.
- [x] Each candidate reports pain point, proposed case/phase, reason, evidence,
  evidence count, independent-session count, overlap, confidence, proposed
  importance, and promotion requirements.
- [x] Repeated evidence may strengthen confidence without silently changing
  owner-set importance or product behavior.
- [x] Existing suite overlap is checked before proposing a new case.
- [x] The skill returns readable text or validated canonical JSON and does not
  edit eval definitions.
- [x] A consumer can distinguish ready existing-behavior candidates from new or
  ambiguous behavior, policy choices, and material cost changes.
- [x] Session-instruction injection, secret-like content, unrelated private
  context, and oversized evidence are safely bounded or rejected.

## Technical Details

- Keep storage neutral; accept selected sanitized evidence and write only an
  explicit result path.
- Use direct progressive references for candidate calibration and privacy.
- Add behavioral cases for recurrence, deduplication, overlap, ambiguity,
  privacy, and no-candidate outcomes.
