# Task: Add paired harness experimentation

## Description

Deliver `eval-harness-experiment`, a bounded orchestrator that tests selected
harness or instruction variants against paired baseline observations in
disposable workspaces and returns ranked evidence plus candidate patches.

## Acceptance Criteria

- [x] Caller-owned input selects one objective, editable surfaces, suites,
  profile, agent/model configuration, tolerances, and cumulative budget.
- [x] Baseline and every candidate use matching relevant conditions and separate
  disposable workspaces.
- [x] The skill never edits the active checkout and never publishes, approves,
  merges, deploys, installs dependencies, or changes permissions.
- [x] `clear_improvement` requires objective improvement beyond tolerance across
  required repetitions, all required cases passing, no material guardrail
  regression, and no effect or budget breach.
- [x] `tradeoff`, `inconclusive`, `no_improvement`, and `incomplete` are retained
  rather than coerced into a winner.
- [x] Visible development cases guide iteration while hidden stable holdouts and
  protected regression cases control final ranking.
- [x] The loop stops on budget exhaustion, target achievement, repeated no
  progress, source/scope drift, forbidden effects, or consequential decision.
- [x] Output contains canonical ranked evidence and candidate patches bound to
  exact starting content; applying a patch remains a separate reviewed action.

## Technical Details

- Consume validated `project-eval` run receipts rather than reconstructing or
  rerunning producer steps inside judging agents.
- Keep optional variant generation separate from deterministic execution and
  comparison authority.
- Add counterexample cases for overfitting, noisy wins, cost-only wins below the
  quality floor, holdout regression, and live-tree mutation attempts.
