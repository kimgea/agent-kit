# Task: Define canonical audit contract and skill skeleton

## Description

Initialize the independently installable skill and freeze its v1 target,
guidance, authority, recommendation, coverage, limitation, and status contracts
before implementation branches depend on them.

## Acceptance Criteria

- [x] Initialize `skills/verification-harness-audit/` with the repository's
      required skill-creation tooling and only needed resource directories.
- [x] Define a schema-versioned canonical result with lead-owned target,
      guidance, inventory, context, and execution-plan provenance.
- [x] Define semantic draft ownership so an agent cannot expand scope, add
      authority, or choose derived identifiers, counts, or status.
- [x] Freeze recommendation strengths, impact, confidence, readiness, evidence,
      affected locations, safe direction, alternatives, and measured-versus-risk
      semantics.
- [x] Freeze deterministic status precedence: material limitation to
      `INCOMPLETE`, otherwise essential recommendation to `IMPROVEMENTS`,
      otherwise `PASS` with advisory recommendations permitted.
- [x] Document exact v1 exclusions, including first-class command targets,
      external services, edits, dependency installation, and direct fixer
      adapters.

## Technical Details

- Read the skill creator's `openai.yaml` reference before generating Codex
  metadata.
- Keep SKILL frontmatter limited to `name` and `description`.
- Put detailed result authoring and analysis calibration under `references/`;
  keep locked workflow and safety invariants concise in `SKILL.md`.
- Model target and authority as a separately supplied resolver context rather
  than semantic-draft fields.
