# Task: Author audit workflow and repository integration

## Description

Author the concise agent workflow, progressive-disclosure rubric, catalog
metadata, and maintainer documentation needed to make the skill discoverable,
portable, and usable without loading implementation history at runtime.

## Acceptance Criteria

- [ ] `SKILL.md` clearly triggers for test, lint, type-check, build, validation,
      local CI, and harness-quality audits and clearly excludes fixing.
- [ ] Runtime instructions cover harness-centered scope, related context,
      REVIEW precedence, progressive inspection, bounded delegation, execution
      plans, evidence calibration, output selection, and fail-closed behavior.
- [ ] A progressive-disclosure rubric defines coverage, assertion strength,
      discoverability, timing, determinism, isolation, redundancy, platforms,
      CI parity, recommendation strength, and decision calibration.
- [ ] Codex metadata matches the finished skill and contains no unsupported
      optional branding fields.
- [ ] Update `toolkit.toml`, grouped plugin membership, architecture,
      compatibility, README/catalog surfaces, public skill documentation, and
      changelog/version tracking consistently.
- [ ] Document that local CI files are auditable project data while provider
      APIs, remote run state, provider-specific general policy, and agents in CI
      remain out of scope.
- [ ] Document generic `review-and-fix` normalization as optional downstream use
      without promising a deterministic adapter.

## Technical Details

- Keep everyday locked workflow and safety decisions in `SKILL.md`; place the
  detailed audit rubric and result-authoring contract in directly linked
  references; keep maintainer and compatibility history under `docs/`.
- Keep `SKILL.md` below 500 lines and avoid standalone README or changelog files
  inside the installed skill.
