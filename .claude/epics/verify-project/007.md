# Task: Integrate verify-project with review-and-fix

## Description

Add an optional deterministic consumer path that makes fresh canonical
verification the post-fix evidence gate while preserving independent packaging,
target ownership, command authority, and the existing fallback.

## Acceptance Criteria

- [x] Add a `verify-project` runtime profile and deterministic adapter only after
      the standalone schemas and behavior are frozen.
- [x] Independently validate producer JSON and require exact lead-owned target,
      plan, context, and freshness binding.
- [x] Route only complete sufficiently covered `pass` results to the fresh
      original reviewer.
- [x] Preserve `fail`, `unknown`, and incomplete outcomes with their safe next
      actions; never translate them into reviewer pass or automatic fixes.
- [x] Prevent verification output from expanding edit scope, granting command
      authority, choosing plans, or supplying reviewer acceptance.
- [x] Retain and accurately label the existing bounded validation fallback when
      `verify-project` is not installed.
- [x] Add consumer behavioral cases for pass, failure, incomplete, unknown,
      stale, target-mismatched, forged-authority, non-fresh, and absent-skill
      paths.

## Technical Details

- Keep the adapter inside `review-and-fix`; do not import `verify-project` as a
  Python runtime library.
- Use producer validation through its own explicit command surface when the
  skill is available, then convert only after exact target comparison.
- Preserve separate final reviewer acceptance after verification.
