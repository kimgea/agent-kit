# Task: Define skill skeleton and canonical contracts

## Description

Initialize the independently installable skill and freeze its v1 target,
guidance, authority, plan, evidence, mutation, state, and output contracts before
implementation streams depend on them.

## Acceptance Criteria

- [ ] Initialize `skills/verify-project/` with the repository's skill-creation
      tooling and only the resource directories required by the approved design.
- [ ] Define separate schema-versioned verification-plan and
      verification-result contracts.
- [ ] Define the lead-owned target and authority context and the fields an
      agent-authored semantic draft may supply.
- [ ] Freeze current-filesystem target kinds, progressive tiers, effect classes,
      completion/outcome/next-action axes, and status precedence.
- [ ] Freeze canonical claim, check, limitation, observation, freshness, and
      bounded diagnostic-evidence shapes.
- [ ] Document v1 role boundaries and exclusions, including no review, triage,
      fixes, generic command runner, dependency installation, or external access.

## Technical Details

- Read the skill creator's `openai.yaml` reference before generating metadata.
- Keep skill frontmatter limited to `name` and `description`.
- Put detailed schema and authoring rules in directly linked references.
- Ensure neither semantic plan nor result drafts can add scope, authority,
  allowed effects, freshness, IDs, fingerprints, or derived state.

## Dependencies

- Approved `.claude/prds/verify-project.md`.

## Effort Estimate

- Size: M
- Hours: 5

## Definition of Done

- [ ] Skeleton and canonical contracts implemented.
- [ ] Schema and metadata validation pass.
- [ ] Contract reviewed against PRD and existing trust boundaries.
