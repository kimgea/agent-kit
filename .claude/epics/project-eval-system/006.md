# Task: Add eval suite lifecycle audit

## Description

Deliver the analysis-only `eval-suite-audit` skill for keeping evaluation suites
useful, compact, current, and economical without equating age or success with
obsolescence.

## Acceptance Criteria

- [ ] The skill audits selected committed definitions plus explicitly supplied
  compatible evidence and never edits definitions by default.
- [ ] Recommendations use `keep`, `refresh`, `merge`, `simplify`, `demote`, or
  `retire` and include strength, reason, confidence, evidence, unique coverage,
  replacement coverage, cost effect, and limitations.
- [ ] Age, always passing, and no recent caught defect are insufficient on their
  own to retire a case.
- [ ] Retirement requires evidence of removed behavior, duplicate/superseded
  coverage, obsolete fixture/architecture, no unique agent-behavior value, or
  high cost without unique coverage.
- [ ] Adding a case first checks extension, parameterization, merging, or
  replacement of current coverage.
- [ ] Compaction recommendations may appear at any suite size and become more
  aggressive as context and run cost grow.
- [ ] Meaningful coverage loss, behavior change, or material cost increase is
  marked decision-required; ready behavior-preserving maintenance is clearly
  separable for an authorized consumer.
- [ ] Human and JSON reports derive from one canonical result.

## Technical Details

- Keep storage neutral and accept portable/imported results as evidence only.
- Delete retired cases from the current tree only when a later authorized actor
  applies the recommendation; Git history is the archive.
- Add behavioral cases for unsafe retirement, safe merging, stale fixtures,
  high-cost duplicates, unique regressions, and compact healthy suites.

## Dependencies

- Task 001 protocol family.
- Task 004 definitions, receipts, and comparison semantics.

## Definition of Done

- [ ] Skill, canonical helper, schema, docs, tests, and evals implemented.
