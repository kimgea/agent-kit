# Task: Add eval candidate audit

## Description

Deliver the analysis-only `eval-candidate-audit` skill for turning explicitly
selected session evidence into bounded, deduplicated evaluation candidates.

## Acceptance Criteria

- [ ] The skill accepts only caller-selected or project-opted-in eligible
  session inputs and never performs global automatic transcript analysis.
- [ ] Private raw transcripts remain local and are neither committed nor copied
  into portable candidate output.
- [ ] Each candidate reports pain point, proposed case/phase, reason, evidence,
  evidence count, independent-session count, overlap, confidence, proposed
  importance, and promotion requirements.
- [ ] Repeated evidence may strengthen confidence without silently changing
  owner-set importance or product behavior.
- [ ] Existing suite overlap is checked before proposing a new case.
- [ ] The skill returns readable text or validated canonical JSON and does not
  edit eval definitions.
- [ ] A consumer can distinguish ready existing-behavior candidates from new or
  ambiguous behavior, policy choices, and material cost changes.
- [ ] Session-instruction injection, secret-like content, unrelated private
  context, and oversized evidence are safely bounded or rejected.

## Technical Details

- Keep storage neutral; accept selected sanitized evidence and write only an
  explicit result path.
- Use direct progressive references for candidate calibration and privacy.
- Add behavioral cases for recurrence, deduplication, overlap, ambiguity,
  privacy, and no-candidate outcomes.

## Dependencies

- Task 001 protocol family.
- Task 004 definition and bundle contracts.

## Effort Estimate

- Size: L
- Hours: 5-7

## Definition of Done

- [ ] Skill, canonical helper, schema, docs, tests, and evals implemented.
- [ ] Analysis-only and privacy boundaries are proven.
- [ ] Standalone package is self-contained.
- [ ] Code reviewed.
